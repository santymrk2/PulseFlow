# Contexto del Proyecto: Migración de Electron a Tauri

Estamos migrando la aplicación FreeShow de Electron (Node.js) a Tauri (Rust).
El frontend en Svelte/TypeScript se mantiene, pero todo el backend se reescribe en Rust.

## Reglas Estrictas para el Agente (Rust & Tauri)

1. **No inventes librerías de Node.js en Rust:** Reemplaza `fs`, `path`, `child_process` de Node por las librerías estándar de Rust (`std::fs`, `std::path`) o `tokio` para asincronía.
2. **Seguridad de Memoria:** Prohibido usar `.unwrap()` o `.expect()` en el código de producción de Rust. Maneja siempre los errores devolviendo un `Result<T, String>` o usando tipos de error personalizados que implementen `serde::Serialize` para enviarlos al frontend.
3. **IPC (Comunicación Inter-Procesos):** Los `ipcMain.handle` de Electron deben traducirse a `#[tauri::command]` en Rust.
4. **Tipado Estricto:** Toda interfaz de TypeScript que viaje entre el frontend y el backend debe tener su equivalente exacto como un `struct` de Rust con `#[derive(Serialize, Deserialize)]`.
5. **Aislamiento:** No modifiques los archivos `.svelte` a menos que se te pida explícitamente actualizar la llamada de `ipcRenderer` a `@tauri-apps/api/core`.
6. **Gestor de Paquetes (Bun):** Este proyecto utiliza estrictamente `bun` como runtime y gestor de paquetes para el ecosistema web.
   - NUNCA sugieras ni ejecutes comandos con `npm`, `yarn` o `pnpm`.
   - Usa siempre `bun install`, `bun run` o `bunx`.
   - El lockfile oficial es `bun.lockb`.
